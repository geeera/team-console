What you are approving

What you are approving. How “Team jobs” and Run now look on a project that still keeps its tasks in GitHub Issues (#775, PR 3b), once a runner can serve it: iPhone at 375 px first, then the Mac, light and dark, ru and en. Flow, states and copy follow the UX spec on #775 with the architect’s §8 and the security note (R-RUN, Q8). The board is #766’s; nothing new is invented where the app has a part.

  • Where it sits. The board’s Runs section (the side column on the Mac, the Runs tab on the iPhone) now holds two blocks: “Team jobs” (tc-board-jobs: Run now, Now and queued, Recent jobs, with tc-job-card) and under it “GitHub run log” (tc-sprint-run-list, unchanged, with Full run log). A console-tracker project shows only the first. The Runs tile in the stats keeps the run log on a GitHub-tracker project (owner question 2).
  • Run now offers six kinds: PM, dev and QA slots, Burn-down, Security audit, Digest. Review and PM chat are allowed by the API and start from their own places; Import and Kickoff are never offered. If the server still refuses a kind, the line under Run says so in clay and nothing is queued.
  • Availability, from the tile DTO (runnerAvailability, the same answer the claim filter gives, so members see it too): ready adds no line; offline and paused are an ochre line above the form (Run still works, the job waits; the owner sees until when and a Runners link); none replaces the form with a block that names the cause and one way out.
  • None. Owner: “No runner serves this project” with Open Settings › Runners. Member: the same title, and who can connect one (the owners, by name). D3 on a two-owner account, if the owner answers “no”: the other owner sees “This runner doesn’t serve your projects” with Connect a runner; the runner’s owner sees “Your runner doesn’t serve this project” with Open the runner. Both carry “Why” (a subscription is personal).
  • Members get no form and no header Run: one quiet line “Only the account owner can start jobs — Anna.” The jobs list stays readable; runner names show as the id tail, as today.
  • Motion. Only the queued card slides in (240 ms); reduced motion: a 120 ms fade.

Try: press Run in the Runs section (or the header Run, which takes you there). Switch the state to offline and press Run again. Pick “none”, then “member”. Pick a D3 state: the page sets two owners.

Colour
Paper Desk tokens only. Ochre: offline, paused, a running job. Moss: a finished job. Clay: a failed job, a refused Run. Grey: queued, none, the member line.

Что вы утверждаете. Как «Задачи команды» и «Запустить» выглядят на проекте, который ещё ведёт задачи в GitHub Issues (#775, PR 3b), когда его может обслужить раннер: сначала iPhone 375 px, потом Mac, светлая и тёмная тема, русский и английский. Сценарий, состояния и тексты — по UX-спеке на #775 с §8 архитектора и заметкой безопасности (R-RUN, Q8). Доска — из #766; где в приложении уже есть деталь, нового не придумано.

  • Где это. В разделе «Прогоны» доски (правая колонка на Mac, вкладка «Прогоны» на iPhone) теперь два блока: «Задачи команды» (tc-board-jobs: «Запустить сейчас», «Сейчас и в очереди», «Последние задачи» с tc-job-card) и под ним «Журнал прогонов GitHub» (tc-sprint-run-list без изменений, со ссылкой «Весь журнал прогонов»). На проекте с трекером консоли — только первый. Плитка «Прогоны» в статистике на GitHub-проекте по-прежнему читает журнал (вопрос владельцу 2).
  • «Запустить» предлагает шесть видов: слоты PM, разработки и QA, «Добор задач», «Аудит безопасности», «Сводка». Ревью и чат с PM API разрешает, но запускаются они со своих мест; «Импорт» и «Старт проекта» не предлагаются никогда. Если сервер всё же отклонил вид, строка под кнопкой скажет это цветом глины, и ничего не встанет в очередь.
  • Доступность — из DTO плитки (runnerAvailability, тот же ответ, что даст фильтр claim, поэтому её видят и участники): готов — без строки; не в сети и на паузе — охристая строка над формой («Запустить» работает, задача ждёт; владелец видит, до какого времени, и ссылку «Раннеры»); нет — вместо формы блок, который называет причину и один выход.
  • Нет раннера. Владелец: «Нет раннера для этого проекта» и «Открыть Настройки › Раннеры». Участник: тот же заголовок и кто может подключить раннер (владельцы по имени). D3 на аккаунте с двумя владельцами, если ответ «нет»: другой владелец видит «Этот раннер не обслуживает ваши проекты» и «Подключить раннер», владелец раннера — «Ваш раннер не обслуживает этот проект» и «Открыть раннер». У обоих — «Почему так» (подписка личная).
  • Участники не видят формы и «Запустить» в шапке: одна спокойная строка «Запускать задачи может владелец аккаунта — Анна.» Список задач читается; имя раннера — хвост id, как сейчас.
  • Движение. Только новая карточка в очереди выезжает (240 мс); при «Меньше движения» — затухание 120 мс.

Попробуйте: нажмите «Запустить» в разделе «Прогоны» (или «Запустить» в шапке — она переведёт туда). Переключите состояние на «не в сети» и запустите ещё раз. Выберите «нет подходящего раннера», затем «участник». Выберите состояние D3 — страница поставит двух владельцев.

Цвет
Только токены Paper Desk. Охра — не в сети, пауза, задача выполняется. Мох — задача завершена. Глина — сбой, отклонённый запуск. Серый — в очереди, нет раннера, строка участника.
